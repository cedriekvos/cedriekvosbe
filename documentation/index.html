Documentation

Everything written down about this codebase, in one place. Each section answers a different question, so pick the one that matches yours. The menu at the top of every page brings you back here.

Sections

Architecture

What is this codebase made of, and how do the pieces fit?

The module map, the anatomy of a domain, what happens on a request and what depends on what. Generated from the source, so it cannot drift.

Specifications

What exactly does the application do?

A Gherkin spec for every behavior, a Dutch leesmij beside each one explaining why, and the trace from each scenario to the acceptance test that checks it, with every place that chain breaks.

Decisions

Why was this technical choice made, and what lost?

Architecture Decision Records: one cross-cutting technical decision per page, the rule it puts on the code, and the options that were rejected.

Lessons

How does this code use PHP, and why is it shaped this way?

PHP features, practices and design patterns, taught from real snippets of the codebase and what each choice costs. The snippets are checked against the code in QA.

Where to start

  1. Architecture, then its module map, for the shape of the whole thing.
  2. The specifications when you need to know exactly what a feature does, and which test proves it.
  3. The lessons in order, for how the code is written and why.
  4. The decisions whenever a rule in the code looks odd: the record behind it explains what it protects.
