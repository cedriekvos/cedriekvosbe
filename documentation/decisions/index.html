Architecture Decision Records

cedriekvos/blog · 9 decisions

The project’s cross-cutting technical decisions, one per page. This is the counterpart to documentation/specifications/leesmij/: where a leesmij records why a behavior is what it is, an ADR records why a technical choice was made and what was rejected.

ADRs are owned by the feature-architect skill, which sits between feature-specifier and feature-to-pest in the pipeline and is invoked only when a change raises a foundational technical question — a new dependency, a file or serialization format, a new bounded domain’s storage strategy. Most features raise none and skip it.

Conventions

Filename
ADR pages are NNNN-kebab-title.html, zero-padded 4-digit sequence. Start from template.html and add a row to this index.
Language
English. The leesmij is Dutch; ADRs are not.
One decision per file
If a page decides two things, it is two pages.
Status
Proposed → Accepted / Rejected, later Superseded by NNNN. It lives in the header pill, not in a field list.
Immutable once Accepted
The decision is. Don’t rewrite it to change what was decided: write a new ADR that supersedes it, and point the old one at it. Reformatting, fixing a link, or adding a back-reference to a later ADR is not a rewrite.

House style for the writing

An ADR that nobody rereads has failed, so these are rules, not suggestions.

The title states the decision, not the topic
“Highlight fenced code only” beats “Wire tempest/highlight for fenced code only, not via HighlightExtension wholesale”.
Lead with the decision and its reason
The blockquote under the title carries both. A reader who stops there should still be correctly informed.
Shape: The rule · Why · Why not · Fallout
The rule comes first because the usual reader is the coder looking for a constraint. From three options up, Why not is a table — the argument should be visible as structure, not prose.
Budget the prose: one screen
Tables, snippets and <details> blocks don’t count; everything else does. Past that, something on the page is not a decision. A genuinely small decision gets the one-paragraph form.
Cite, don’t paste
A path and a line number, not a quoted block of vendor source. Pasted vendor code goes stale silently.
No process narration
Not who discovered what, not which skill read which file, not what was asked in what order. Only what is true and what it costs. “Rejected by the user” is worth one clause when it explains an otherwise odd choice; the deliberation is not.
Evidence longer than the decision
Goes in a collapsed <details> block.
