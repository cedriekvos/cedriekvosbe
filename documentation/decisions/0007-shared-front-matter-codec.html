A shared front-matter codec in App\Markdown

We extract the fence/YAML mechanics into a new top-level App\Markdown namespace and leave every domain mapping where it is — the format code is duplicated character-for-character across Blog and Microblog, and it belongs beside symfony/yaml, not inside either domain.
Driver
documentation/architecture-review-20260722.html, candidate A — an internal refactoring with no externally visible behavior, for which the user declined a behavioral spec
Related
Scopes, but does not supersede, ADR 0002. The plain converter it left in App\Blog moves here in ADR 0009.

The rules

  • App\Markdown\FrontMatterDocument — final readonly value object holding array<string, mixed> $frontMatter and string $body.
  • App\Markdown\FrontMatterParser — parse(string $contents): FrontMatterDocument. Owns fence detection, Yaml::parse, and the no-front-matter fallback (the whole file becomes the body, front matter empty).
  • App\Markdown\FrontMatterSerializer — serialize(array $frontMatter, string $body): string. Owns CRLF normalisation of the body, Yaml::dump, and the fence join.
  • Parse and serialize are two responsibilities and get two classes; boundaries beyond that are feature-development's call, as in ADR 0002.
  • Domain-owned mapping stays put. PostFileParser keeps the slug default from the filename and the body/content/excerpt/read_time_minutes derivation; MessageFileParser keeps the id default from the filename; PostFileSerializer keeps its array_filter front-matter assembly and MessageFileSerializer its id/posted_at pair. All four keep their current public signatures and return shapes, and delegate via constructor injection.
  • Parsing stays LF-only, deliberately. The codec normalises CRLF on serialize only, exactly as today; the parser keeps detecting the fence with the literal ---\n and \n---\n, so a CRLF-authored file still has its front matter unrecognised and falls through as body. That is a latent bug, and this ADR deliberately does not fix it — widening parse tolerance under a behavior-preserving refactor with no spec would be an unspecified, user-visible change. Recording it here means the extraction cannot quietly widen it either. Making the parser CRLF-tolerant is a new feature: file it through feature-specifier.
  • App\About is out of scope. AboutFileParser/AboutFileSerializer call Yaml:: too, but they are bare YAML — no fence, no body. They are not front-matter documents and must not be pulled in by the review's “N content domains” framing.

Why

The format is implemented twice, and the duplicated halves are identical:

FileDuplicated role
app/Blog/Markdown/PostFileParser.phpsplit fence + Yaml::parse
app/Blog/Markdown/PostFileSerializer.phpYaml::dump + join fence + CRLF trim
app/Microblog/Markdown/MessageFileParser.phpsplit fence + Yaml::parse
app/Microblog/Markdown/MessageFileSerializer.phpYaml::dump + join fence + CRLF trim

Only the field mapping differs. ADR 0002 did bless the Blog/Microblog duplication, but it reasoned about domain layering from domain shape and never weighed the serialization format; that stance holds in full here — the Source/Factory/Get/Write/facade stacks, the sorters, and the domain parsers and serializers all stay duplicated per domain. What moves is format mechanics, which sit alongside a dependency both domains already require directly, and are therefore not a domain concern. symfony/yaml is already a direct require, so no dependency is at stake.

Why not

OptionWhy not
Leave the duplication, citing ADR 0002Over-reads 0002: its reasoning is about domain shape and says nothing about file format. The cost is concrete — four copies of the fence edge cases, tested twice, drifting on any change
One FrontMatterCodec with parse() and serialize()Fewer files and one injection point, but bundles two responsibilities against house style and makes every read path depend on the write path for nothing
App\Support\FrontMatter\Conventional Laravel, but no Support folder exists here and every other app/ folder names a real thing; generic buckets accrete unrelated helpers. Rejected by the user
App\Content\Markdown\Introduces a second grouping concept nothing else in app/ uses, and About — a content domain — would sit outside it. Rejected by the user
Keep the codec in App\Blog\Markdown and have Microblog depend on itAvoids a new base folder, but makes Microblog import a Blog class for generic format handling — the exact scope leak the review objects to elsewhere
Normalise CRLF on parse as part of the extractionFixes a real latent bug, but is new externally visible behavior on hand-authored, git-tracked files with no spec and no test to pin it

Fallout

  • New top-level App\Markdown\ namespace, approved by the user. PSR-4 already maps App\ → app/ and all three classes are argument-free, so there are no autoload or container changes.
  • The four existing unit tests are the proof of correctness, together with the blog/microblog admin write-path feature tests. Their assertions must not change — only construction lines may, where a class gains a dependency. A test that has to be relaxed to make the refactor pass means the refactor changed behavior and is wrong.
  • Serializer output must stay byte-identical for every input the two domains produce today, including the blank line after the closing fence and the trailing newline: the files are git-tracked, and a whitespace shift would show up as a diff on the next save of every post and message.
  • Each new class owes a covers()-scoped unit test, and the change must land a green composer qa.
  • app/Blog/Markdown/PostFileParser.php is the only one of the four missing declare(strict_types=1); — add it while the file is open.
  • A third front-matter consumer now costs one constructor argument instead of a copied block. App\About is not that consumer.
  • Review candidate B (lifting PostMarkdownToHtmlConverter out of App\Blog) would land naturally in this namespace but contradicts ADR 0003/ADR 0004 and is explicitly not decided here.
  • Superseding trigger: a future domain needing a genuinely different front-matter dialect (different fence, TOML, multi-document) reopens this ADR rather than the codec growing mode flags.
