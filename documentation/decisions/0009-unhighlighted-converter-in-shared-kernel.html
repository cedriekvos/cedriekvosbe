0009 Accepted 2026-10-20

The unhighlighted Markdown converter lives in App\Markdown

We keep one converter without highlighting in App\Markdown, used by About and Pages, instead of a Blog class that only About calls — the unhighlighted bio depends on About using a converter without the highlight extension, not on where that converter lives.
Driver
Architecture review of 2026-10-20
Related
Corrects part of point 2 of ADR 0003: where the plain converter lives and what it is called. The post-only highlighted converter and the rest of 0003 stand. Decides the question ADR 0007 left open.

The rule

  • One class in App\Markdown (indicative name ProseMarkdownToHtmlConverter) wraps MarkdownToHtmlConverter with CommonMarkCoreExtension and ExternalLinkExtension only. It never gets FencedCodeHighlightExtension.
  • App\About\AboutFactory and App\Pages\Markdown\PageFileParser depend on it. App\Blog\Markdown\PostMarkdownToHtmlConverter and App\Pages\Markdown\PageMarkdownToHtmlConverter go.
  • Highlighting stays Blog-only, in App\Blog\Markdown\HighlightedPostMarkdownToHtmlConverter.
  • App\About no longer uses App\Blog, so tests/Architecture/DomainTest.php drops App\Blog from About's allowlist.
php
// app/About/AboutFactory.php
public function __construct(
    private ProseMarkdownToHtmlConverter $proseMarkdownToHtmlConverter,
) {}

Why

ADR 0003 kept the plain converter in App\Blog so the About bio would stay unhighlighted by construction. That guarantee comes from About depending on a converter without the highlight extension; the namespace adds nothing to it. In App\Blog the class serves no Blog code. About is its only caller, which makes it the one cross-domain exception in DomainTest, and Pages carries an identical copy because it may not use App\Blog. App\Markdown is the shared kernel every domain may use, so one class there serves both and the exception goes away.

Why not

OptionWhy not
Keep ADR 0003's placementA Blog class that only About calls, an allowlisted dependency of About on Blog, and a copy in Pages that has to change in step with it.
Move it into App\About; Pages keeps its ownRemoves the exception but keeps two identical classes.
One MarkdownToHtmlConverter with a contextual binding per consumerAlready rejected in ADR 0003: the extension list disappears from the consumer's constructor.

Fallout

  • The bio and Pages now render through the same class, so a change to it changes both. A need for them to differ reopens this ADR.
  • Highlighting the bio or Pages later means a separate converter, as ADR 0003 did for posts — never adding the extension to this one.
  • The plain converter needs no excerpt(): neither consumer calls it, and post excerpts come from the highlighted converter. The exact shape is left to feature-development.
  • The module map under documentation/architecture/ is regenerated with generate.php.
