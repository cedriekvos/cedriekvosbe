The shape of a class: Post and its factory

Every class in the five domains and the Markdown kernel has the same shape: strictly typed, final, readonly, with its data or its dependencies passed in through a promoted constructor. This lesson uses the smallest example, the blog’s Post and the factory that builds it. It covers what each keyword buys you, which pattern the code actually follows (not quite the one the architecture pages label it with), and how the rules are enforced rather than left to good intentions.

PHP features

strict_types · readonly classes 8.2 · constructor promotion 8.0 · named arguments 8.0 · mixed 8.0 · typed class constants 8.3

Patterns

Value object vs. immutable snapshot · Factory · Named constructor (the road not taken)

Practices

Immutable by default · final by default · narrow mixed at the boundary · rules enforced by tests

1 · The declaration

Nine properties, no behaviour

  • declare(strict_types=1) applies to calls made from this file, not calls into it. Post.php makes no calls, so here the line only follows the house rule. Where it matters is PostFactory.php, which calls new Post(…). A file without the declare can still pass '3' for $read_time_minutes and have it quietly coerced to 3. The setting belongs to the caller, which is why the codebase requires it in every file rather than relying on the receiving side.
  • A readonly class (PHP 8.2) makes every property readonly. Each property can be initialised once, from inside the class, and dynamic properties are an Error. Combined with promotion, the constructor is the only place a Post’s state is ever set. There is no setter to forget about and no half-built object.
  • final takes inheritance off the table. PHP already requires a child of a readonly class to be readonly too, so this is not about mutability. It means that changing what a class does here is done by composing it, never by subclassing and overriding.
  • Defaults sit at the tail. Since PHP 8.0, an optional parameter before a required one is deprecated, so the two flags with sensible defaults go last.
  • An oddity worth noticing: snake_case property names. The methods are camelCase, and so are the Livewire properties built from these ($this->isDraft). read_time_minutes matches the array key the parser produces, and Blade views read these names directly, so renaming one is a change across layers, not a local tidy-up.

2 · The pattern

What the codebase calls a value object

The generated architecture pages assign every class a role, and Post has this one:

By the textbook definition (Evans, Fowler), a value object has no identity, so two are interchangeable when their values match, and it protects its own invariants. Post does neither. It has an identity, the slug: a post whose title you fix is still the same post. And it validates nothing, so new Post(read_time_minutes: -4, date: 'whenever', …) constructs without complaint. The test helper is more candid about what it is:

The accurate name is an immutable snapshot of an entity. The entity is the Markdown file on disk, and a Post is what that file said when it was read. That works because Post is only ever read. The write side never takes one: it gets plain attributes and writes the file.

An object with no lifecycle has no invariants to defend over time, so leaving the constructor dumb is a reasonable trade. The cost shows up wherever meaning is needed and only a type is guaranteed. $date is a string, so every consumer that needs a point in time has to parse it again, and has to decide what a failed parse means:

A DateTimeImmutable $date would move that decision into the factory, made once. Keep this in mind as a refactoring candidate. It is also the general rule: a type you can trust is cheaper than a check you repeat.

3 · The factory

Where mixed stops

  • This is the boundary. $data is YAML front matter that a person typed, so its values are mixed. PHPStan runs at its strictest level, where a mixed value cannot be passed to a string parameter until something has narrowed it. The three private helpers do that narrowing, and past this method nothing in the domain has to wonder about types again.
  • It never throws. A missing title becomes '' and a bad read time becomes 1. That is a deliberate preference for availability over strictness: one malformed file renders with blanks instead of taking the index page down with it. The price is silence, because a typo such as titel: produces an untitled post and no error.
  • is_bool($value) && $value, not (bool) $value. Casts are the trap: (bool) 'no' is true. Checking the type means only a real YAML boolean can feature a post.
  • Named arguments (PHP 8.0) carry the mapping. There are nine parameters, five of them strings in a row. Called positionally, swapping excerpt and body would type-check and be wrong. With names, the call reads as the mapping it is. The price is that parameter names become part of the API: renaming $is_draft breaks every named call. The test helper went the other way: renaming a parameter leaves it untouched, but swapping two of the string parameters would silently scramble every post it builds.

Why a separate class at all? The common alternative is a named constructor on the object itself:

It would work, and for a factory with no dependencies it is not obviously worse. The codebase chooses consistency instead. Post stays ignorant of front matter, so it does not know YAML exists. Every role in a domain is a class injected through a constructor, so a factory that does need a collaborator later fits without changing its shape. The cost is one extra class per domain.

4 · Services

Readonly without any state

PostFactory has no properties at all, yet it is declared final readonly too, and so are the services around it:

  • On a stateless service, readonly is a promise about the future. Any property someone adds later has to be set in the constructor and can never change. A service that cannot accumulate state behaves the same whether the container hands you a shared instance or a new one, and that is the property you want from a service.
  • Dependencies are promoted private parameters. Laravel’s container autowires a concrete class by its constructor types, so PostFilter gets its DraftSlug without any binding in a service provider. The constructor is the dependency list, and nothing else declares one.
  • Typed class constants (PHP 8.3). const string PREFIX stops a subclass or implementing class from redefining the constant with another type. On a final class nothing can redefine it anyway, so here the type is documentation that PHPStan reads, and that is reason enough.

5 · Enforcement

Enforced by tests, not by good intentions

One mutation Pest tries is turning && into || in boolOrFalse(). A test that only feeds it true and a missing key would still pass, because both versions agree on those inputs. That is the habit to take from this lesson. Coverage only proves that a line ran. Mutation testing at 100% proves that a test would fail if the line were different, so every branch of a boundary function like this one has a test that depends on it.

Check yourself

Four questions

Answer each one before you open it. Opening the answer first teaches you much less.

1Which of these front-matter values make is_featured true: true, "true", 1, "no"? And with (bool) $value?

Only true. With a cast, all four would: any non-empty string other than "0" casts to true, and so does any non-zero number, so "no" would feature a post. A cast converts a value; a type check narrows it.

2A compiled Blade view, which has no strict_types declare, runs new Post(…, read_time_minutes: '3'). TypeError, or a post with 3?

A post with 3. Strict mode for a call is decided by the file the call is written in, not the file that declares the function. The same line inside PostFactory.php throws a TypeError. That is why the rule is “every file declares it”, not just “the class being called declares it”.

3Why does make() take bool $isDraft as its own argument instead of reading it from $data? Look at its caller.

Draft status is not front matter. It is encoded in the stored slug, the draft- prefix on the file name, and only storage knows about that. Passing it in separately means a post cannot publish itself by writing is_draft: false in its own front matter, because the factory never looks at that key. Each fact has one source.

4Find a class in app/ that is neither final nor readonly, and explain why it cannot be.

Any Livewire component, such as this one. Livewire writes to public properties on every request, which is how wire:model works, so readonly is impossible, and the component extends a framework base class. That is why the architecture rule covers the domains and the kernel only: the delivery layer is where mutable, framework-shaped code is allowed to live. The @pest-mutate-ignore comment is a preview of a later topic, a mutation that is deliberately not tested.
